三、模块一：文档上传与解析
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│                              文档上传与解析                                       │
└─────────────────────────────────────────────────────────────────────────────────┘

  前端上传文件
       │
       │ POST /api/v1/documents/upload (multipart/form-data)
       │ - file: 文件
       │ - sourceType: 来源类型 (manual_upload)
       │ - equipmentType: 设备类型 (如 "通用型")
       │ - persistToKnowledgeBase: 是否持久化到知识图谱
       ▼
┌──────────────────────────────────────┐
│  DocumentController.uploadDocument()  │
│  [DocumentController.java]           │
└──────────────────────────────────────┘
       │
       │ 1. 生成 docId (UUID)
       │ 2. 保存文件到磁盘
       │ 3. 发送 RabbitMQ 消息 → queue.document.parse
       ▼
┌──────────────────────────────────────┐
│  DocumentParseListener (MQ Consumer) │
│  [DocumentParseListener.java]         │
│  消费 queue.document.parse           │
└──────────────────────────────────────┘
       │
       │ 4. 读取文件
       │ 5. 解析内容（PDF/DOCX/TXT/CSV/XLSX）
       │ 6. 语义段落提取（因果关系、领域实体）
       │ 7. 调用 VectorStoreClient.processDocument()
       ▼
┌──────────────────────────────────────┐
│  VectorStoreClient (Feign调用)       │
│  → VectorStoreService.processDocument│
│  [VectorStoreController.java]        │
└──────────────────────────────────────┘
       │
       │ 8. 创建 DocumentMetadata
       │ 9. 创建 ParagraphMetadata (按段落)
       │ 10. 生成向量存入 VectorStore
       ▼
┌──────────────────────────────────────┐
│  Oracle 数据库 (fta_vector_db)        │
│  • document_metadata                │
│  • paragraph_metadata                │
│  • vector_store                     │
└──────────────────────────────────────┘

【支持的文件格式】

  • PDF (.pdf)
  • Word文档 (.docx)
  • 文本文件 (.txt)
  • CSV文件 (.csv)
  • Excel文件 (.xlsx)

【关联接口】

  POST   /api/v1/documents/upload              上传文档
  GET    /api/v1/documents/{docId}             获取文档元数据
  GET    /api/v1/documents/{docId}/content     获取文档内容
  GET    /api/v1/documents                     获取文档列表
  DELETE /api/v1/documents/{docId}             删除文档

【关键配置】

  # document-ingest-service / application.yml
  spring:
    rabbitmq:
      host: localhost
      port: 5672
      username: guest
      password: guest
    servlet:
      multipart:
        max-file-size: 100MB
        max-request-size: 100MB

四、模块二：故障树生成（RAG）
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│                              故障树生成（RAG）                                   │
└─────────────────────────────────────────────────────────────────────────────────┘

  前端：输入顶事件描述 + 选择生成模式
       │
       │ POST /api/v1/rag/generate
       │ {
       │   "description": "驱动系统故障",
       │   "equipmentType": "通用型",
       │   "knowledgeDriven": true,
       │   "dataDriven": true
       │ }
       ▼
┌──────────────────────────────────────┐
│  RAG API: /rag/generate (FastAPI)    │
│  [rag_api.py]                        │
│  后台任务异步处理                     │
└──────────────────────────────────────┘
       │
       │ 1. 获取文档内容
       ▼
┌──────────────────────────────────────┐
│  _get_document_content_from_service()│
│  • GET /api/v1/documents/{docId}/content│
│  • GET /api/v1/documents/{docId}/paragraphs│
│  • 组装段落列表                       │
└──────────────────────────────────────┘
       │
       │ 2. 多文档融合
       ▼
┌──────────────────────────────────────┐
│  FusionEngine.fuse()                 │
│  [fusion_engine.py]                  │
│                                      │
│  • 段落聚类（相似度 > 0.7）          │
│  • 冲突检测（矛盾型/缺失型/差异型）  │
│  • 冲突消解（基于可信度权重）        │
│  • 返回融合后的段落 + 统计信息       │
└──────────────────────────────────────┘
       │
       │ 3. 获取相关段落
       ▼
┌──────────────────────────────────────┐
│  Vector Search (BGE-M3)             │
│  • 查询向量相似段落                  │
│  • 返回 top-k 相关内容               │
└──────────────────────────────────────┘
       │
       │ 4. 知识图谱查询
       ▼
┌──────────────────────────────────────┐
│  Knowledge Graph Template Query      │
│  • POST /api/v1/kg/query-template   │
│  • 三层匹配（精确/模糊/设备类型）    │
│  • Levenshtein距离相似度            │
└──────────────────────────────────────┘
       │
       │ 5. 组装提示词
       ▼
┌──────────────────────────────────────┐
│  load_fault_tree_prompt()           │
│  [prompts.py]                       │
│  • 组装提示词模板                    │
│  • 拼接相关段落                      │
│  • 添加模板、知识图谱信息            │
└──────────────────────────────────────┘
       │
       │ prompt
       ▼
┌──────────────────────────────────────┐
│  LLMClient.generate()               │
│  [llm_client.py]                    │
│                                      │
│  • 调用百炼API (DashScope/Qwen-Max) │
│  • 返回结构化故障树JSON             │
└──────────────────────────────────────┘
       │
       │ 6. 解析输出
       ▼
┌──────────────────────────────────────┐
│  FaultTreeGenerator.generate()       │
│  [fault_tree_generator.py]          │
│                                      │
│  • 解析 LLM 输出 JSON                │
│  • 转换为 FaultTreeSchema           │
│  • 为每个节点添加 sourceDetail      │
└──────────────────────────────────────┘
       │
       │ 故障树 JSON + fusionStatistics
       ▼
  返回前端

【关联接口】

  POST   /api/v1/rag/generate                    触发故障树生成
  GET    /api/v1/rag/tasks/{taskId}              获取任务状态
  GET    /api/v1/rag/evidence/{paragraphId}       获取段落证据
  POST   /api/v1/rag/evidence                     批量获取证据

【融合统计 fusionStatistics】

    total_clusters: 5,           // 聚类总数
    total_conflicts: 2,          // 检测到的冲突总数
    resolved_conflicts: 2,       // 已解决的冲突数
    fused_paragraphs_count: 8    // 融合后的段落数
  }

十、消息队列架构
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│                              RabbitMQ                                           │
└─────────────────────────────────────────────────────────────────────────────────┘

  交换机 (Exchange)：
  ├── exchange.document         - 文档处理
  ├── exchange.rag             - RAG生成
  ├── exchange.validation     - 校验
  ├── exchange.feedback       - 反馈
  └── exchange.knowledge-graph - 知识图谱

  队列 (Queue)：
  ├── queue.document.parse     - 文档解析
  ├── queue.rag.generate       - RAG生成
  └── queue.feedback.process   - 反馈处理

  【消息流程】
  文档上传 → exchange.document → queue.document.parse
                              → 解析完成
                              → 可选: knowledge-graph

  故障树生成 → exchange.rag → queue.rag.generate
                          → 生成完成 → 前端推送结果

十二、前后端数据流
================================================================================

┌─────────────────────────────────────────────────────────────────────────────────┐
│  前端 → 后端 → 数据库                                                          │
└─────────────────────────────────────────────────────────────────────────────────┘

  1. 请求发送
     前端 (Vue) → Axios → /api/v1/* → Vite代理 → Gateway (8080)

  2. 网关路由
     Gateway → 根据路径转发到对应微服务

  3. 服务处理
     微服务 → Oracle / Neo4j / RabbitMQ

  4. 响应返回
     数据库 → 微服务 → Gateway → Axios → 前端

  【认证流程】
  1. POST /api/v1/auth/login → auth-service → 返回 JWT token
  2. 前端存储 token 到 localStorage
  3. 后续请求自动携带 Authorization: Bearer {token}
  4. Gateway JwtAuthenticationFilter 验证 token
