（以下仅为核心功能部分的简洁说明）
前端核心功能要求
可视化故障树图形化展示与编辑界面
支持以树状图/逻辑图形式清晰呈现“顶事件—中间事件—底事件”层级结构；
提供交互式节点操作：支持拖拽、缩放、展开/折叠、节点增删、逻辑门（AND/OR等）类型切换；
节点需标注事件名称、类型（顶/中/底）、来源依据（如引用自哪份手册或工单）；
图形布局应自动优化，避免重叠，确保可读性。
AI生成结果与专家修正的协同交互
初始故障树由后端AI生成后，前端需完整渲染并高亮显示AI置信度较低或待确认的节点；
专家修改时（如调整连接关系、修正逻辑门），界面需实时响应，并支持撤销/重做；
修改操作需触发后端逻辑校验请求，并在界面上直观展示AI返回的逻辑冲突提示（如循环依赖、冗余路径等）及优化建议。
知识溯源与透明性展示
每个事件节点支持点击查看其AI提取的原始依据（如手册段落、维修记录片段）；
以侧边栏、悬浮窗或弹窗形式展示结构化溯源信息，确保“可解释性”。
多源数据输入预览与配置入口
提供文件上传区域，支持文本（PDF/TXT/DOC等）、表格（CSV/XLSX）等格式预览；
允许用户指定顶事件及生成偏好（通过自然语言提示词输入框）；
上传后可预览解析后的结构化知识片段，供用户确认后再触发生成。
系统基础体验要求
响应式设计，适配主流分辨率（优先桌面端）；
操作流畅，大规模故障树（>100节点）渲染性能良好；
界面风格简洁专业，符合工业软件审美，突出信息层级与操作引导。
技术选型建议（非强制，供参考）
图形渲染：推荐使用 D3.js、GoJS、AntV G6 或 React Flow 等成熟图可视化库；
框架：React/Vue 等主流前端框架；
与后端通信：RESTful API 或 WebSocket（用于实时校验反馈）；
文件解析预览：可集成 PDF.js、SheetJS 等开源库。
