# 知识驱动+数据驱动混合生成实现方案

## 一、方案概述

### 1.1 什么是"知识驱动+数据驱动"混合生成？

**知识驱动（Knowledge-driven）**：
- 从知识图谱中提取领域知识约束
- 典型故障模式、事件分类规则、逻辑门使用偏好
- 确保生成结果符合工业领域常识

**数据驱动（Data-driven）**：
- 从向量检索获取具体文档证据
- 设备手册、维修记录、行业标准中的实际内容
- 确保生成结果有具体的溯源依据

**混合生成**：结合两者的优势，生成既符合领域知识又有实际数据支撑的故障树。

## 三、核心代码实现

### 3.1 HybridFaultTreeGenerator 类

**文件位置**：`python-service/rag-generation-service/rag_service/hybrid_generator.py`

**核心方法**：

#### `generate()` - 主生成方法

```python
def generate(
    self,
    top_event: str,
    doc_ids: List[str] = None,
    knowledge_template: Dict[str, Any] = None,
    user_preferences: str = None
) -> Tuple[FaultTreeSchema, Dict[str, Any]]:
    """
    混合生成故障树

    流程：
    1. 知识驱动 - 从知识图谱提取约束
    2. 数据驱动 - 从向量库检索证据
    3. 构建混合提示词
    4. 调用LLM生成
    5. 知识校验
    """
```

#### `_extract_knowledge_constraints()` - 知识约束提取

从知识图谱模板中提取：
- 典型故障模式
- 事件分类规则
- 逻辑门使用偏好
- 因果关系约束

#### `_retrieve_relevant_paragraphs()` - 数据检索

从向量库检索相关段落：
- 按相似度排序
- 保留可信度权重
- 限制Top-K数量

#### `_build_hybrid_prompt()` - 混合提示词构建

提示词结构：
```
1. 角色设定
2. 任务说明
3. 知识驱动部分（领域约束）
4. 数据驱动部分（文档证据）
5. 用户偏好
6. 输出要求
```

## 四、提示词模板详解

### 4.1 完整提示词结构

```
你是一位专业的工业设备故障分析专家，擅长构建故障树分析（FTA）。
你将基于两部分信息生成故障树：
1. 领域知识约束（来自知识图谱）
2. 具体文档证据（来自向量检索）

## 任务
请为顶事件 "电机过热" 构建一个完整的故障树。

## 领域知识约束（知识驱动）
请遵循以下领域知识约束来构建故障树：
- 典型故障模式: 振动异常, 温度过高, 转速异常
- 逻辑门使用偏好:
  * 电源问题 通常使用 OR 门
  * 轴承故障 通常使用 OR 门
- 典型因果关系:
  * 润滑不足 → 轴承磨损 → 电机过热

## 文档证据（数据驱动）
以下是从相关文档中检索到的证据段落，请基于这些内容生成故障树：

[证据1] (可信度: 1.0, 来源: 电机维护手册.pdf)
电机过热可能是由电源问题、轴承故障或绕组故障引起的。

[证据2] (可信度: 0.8, 来源: 2025年维修记录.xlsx)
电源问题包括电压不稳定、缺相、过载等。

## 用户偏好
请详细说明每个事件的原因。

## 输出要求
请以JSON格式输出故障树...
```

### 4.2 提示词设计原则

1. **明确角色**：设定为工业设备故障分析专家
2. **双重输入**：同时提供知识约束和数据证据
3. **清晰指令**：明确说明任务要求和输出格式
4. **结构化证据**：为每个证据段落标注可信度和来源
5. **约束优先**：先列出知识约束，再提供数据证据

## 五、数据流转

### 5.1 完整数据流

```
1. 用户请求 → POST /api/v1/rag/generate
   └─ 输入: topEvent, docIds, template, userPreferences

2. 后台任务启动 → BackgroundTasks
   └─ task_id: task_abc123

3. 知识驱动处理
   ├─ 调用 knowledge-graph-service (端口 8083)
   ├─ 解析 knowledge_template
   ├─ 提取典型故障模式
   ├─ 提取逻辑门偏好
   └─ 提取因果关系规则

4. 数据驱动处理
   ├─ 调用 VectorStoreService (端口 8090)
   ├─ 检索相关段落 (Top-K=15)
   ├─ 按相似度排序
   └─ 保留可信度权重

5. 混合提示词构建
   ├─ 拼接角色设定
   ├─ 拼接知识约束
   ├─ 拼接文档证据
   ├─ 拼接用户偏好
   └─ 拼接输出要求

6. LLM 调用
   ├─ 发送提示词到 LLM API (端口 8001)
   ├─ 等待响应 (超时: 60s)
   └─ 接收 JSON 输出

7. 结果解析与校验
   ├─ 解析 JSON 为 FaultTreeSchema
   ├─ 调用 rule-validation-service (端口 8087)
   ├─ 知识图谱校验 (可选)
   ├─ 计算置信度
   └─ 添加溯源证据

8. 存储与返回
   ├─ 存储到 tasks_store
   └─ GET /api/v1/rag/tasks/{task_id} 返回结果
```

## 八、优势与特点

### 8.1 核心优势

1. **知识驱动**：
   - 确保生成结果符合工业领域常识
   - 避免违背物理规律的错误
   - 提供典型故障模式参考

2. **数据驱动**：
   - 基于实际文档内容生成
   - 每个事件都有溯源依据
   - 支持可信度加权

3. **混合优势**：
   - 知识约束保证正确性
   - 数据证据保证实用性
   - 两者结合生成高质量故障树

### 8.2 可扩展性

- 支持单独使用知识驱动模式
- 支持单独使用数据驱动模式
- 支持动态调整知识和数据的权重
- 支持知识图谱校验的开关控制

## 十一、故障排除

### 11.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 知识图谱模板为空 | KNOWLEDGE_GRAPH_SERVICE_URL未配置 | 配置环境变量或使用默认模板 |
| 向量检索无结果 | vector-store-service未启动 | 检查端口8090是否可用 |
| LLM调用超时 | 模型服务不可用 | 检查8001端口和LLM配置 |
| JSON解析失败 | LLM输出格式错误 | 检查fault_tree_generator.py的_extract_json() |
